React Lifecycle & Hooks

A component is just a function that runs over and over. Hooks are how a function that keeps getting thrown away manages to remember things and get chores done.

mount update ×97 unmount
1

A component is a function

No magic. Props go in, a description of the UI comes out. React calls it whenever the picture might need to change.

2

Three moments in a life

Every component lives the same story: it appears, it updates a bunch of times, it disappears. That whole story is the lifecycle.

3

What makes it re-render

Two things only: its state changed, or its parent re-rendered and handed it new props. React never edits the screen by hand — it just runs your function again.

4

useState — memory that survives

Every run throws away the function's local variables. So where does count live? On a shelf outside your function, kept by React. useState just reads your slot on that shelf.

5

useEffect — chores after the paint

Rendering must stay pure: props and state in, JSX out, nothing else. Fetching data, starting timers, talking to the outside world — those are side effects, and they run after the screen is painted.

The second argument decides when the chore repeats:

useEffect(fn)

after every render. Rarely what you want.

useEffect(fn, [])

once, after the first render. "On mount."

useEffect(fn, [count])

after any render where count changed.

And if your chore leaves a mess, return a cleanup function. React runs it before the next effect — and at unmount.

useEffect(() => {
  // the chore
  const id = setInterval(tick, 1000);
  // the cleanup
  return () => clearInterval(id);
}, []);
6

The one rule of hooks

React has no idea which useState is which. It only knows the order you called them in. So: hooks at the top level only — never inside an if, a loop, or after an early return.

7

The rest of the toolbox

Same shelf, different jobs:

useRef

a pocket. Survives re-renders like state, but changing it is silent — no re-render.

useContext

the building's PA system. Read a value from far above without passing props down every floor.

useMemo

a sticky note with a remembered answer. Skip redoing expensive math if the inputs didn't change.

8

If you remember one thing

ui = f(props, state)

  • Your component is a function that React runs again and again.
  • useState is memory that survives the runs — and its setter spins the loop.
  • useEffect is a chore that runs after the paint, with a cleanup for the mess.
